# Wage Slave 记录 / 目标 / 统计模块与数据存储需求

## 1. 本次目标

为 Wage Slave 新增三个已预留功能模块：

- 记录：沉淀每日工时与工资流水。
- 目标：设置收入 / 工时目标并展示完成进度。
- 统计：基于记录数据分析收入、工时和目标达成情况。

同时改造本地数据存储，引入 SQLite 保存历史业务数据，继续使用 JSON 保存应用配置。

## 2. 数据存储改造

### 2.1 存储策略

应用采用本地优先存储，不上传用户薪资、工时、目标或历史记录数据。

配置数据继续保存在：

```text
userData/config.json
```

业务历史数据新增 SQLite 数据库：

```text
userData/wage-slave.db
```

### 2.2 数据职责划分

`config.json` 保存低频、少量、偏设置类数据：

- 薪资模式。
- 日薪 / 月薪金额。
- 工作时间、午休时间。
- 工作日配置。
- 主题、透明度、窗口行为。
- 隐私金额模式。
- 天气城市等应用配置。

`wage-slave.db` 保存可增长、可查询、可统计的业务数据：

- 每日工资记录。
- 手动修正记录。
- 目标数据。
- 记录变更事件。
- 后续可扩展统计快照。

### 2.3 初始数据表

#### daily_records

用于保存每日工资与工时记录。

字段建议：

```text
id
date
workday_type
work_start
work_end
break_start
break_end
worked_minutes
earned_amount
salary_mode
salary_snapshot
note
created_at
updated_at
```

要求：

- `date` 按自然日唯一。
- `salary_snapshot` 保存当日计算时的薪资配置快照。
- 用户后续修改薪资配置时，不应影响历史记录金额。
- 支持自动生成，也支持用户手动修正。

#### goals

用于保存目标。

字段建议：

```text
id
period_type
period_key
target_amount
target_workdays
target_minutes
status
created_at
updated_at
```

要求：

- MVP 先支持月目标。
- `period_key` 示例：`2026-06`。
- 目标可以基于当前月薪自动生成，也可以用户自定义。

#### record_events

用于保存记录变更轨迹。

字段建议：

```text
id
record_id
event_type
payload
created_at
```

要求：

- 保存用户补录、修正、备注变更等事件。
- 方便后续做审计、撤销或展示修改历史。

## 3. 记录模块

### 3.1 模块定位

记录模块负责保存每日工时与工资流水，是统计和目标模块的数据基础。

### 3.2 核心功能

- 自动生成每日记录。
- 查看历史记录列表。
- 按月份筛选记录。
- 查看单日详情。
- 手动补录记录。
- 手动修正记录。
- 添加记录备注。
- 导出记录数据。

### 3.3 自动记录规则

应用应在每日产生一条工资记录，记录内容包括：

- 日期。
- 是否工作日。
- 工作开始时间。
- 工作结束时间。
- 午休时间。
- 实际有效工时。
- 今日已赚金额。
- 薪资模式。
- 当日薪资配置快照。

记录生成时机：

- 应用运行中，按当天实时计算结果更新当日记录。
- 当天结束后，记录应稳定为最终结果。
- 如果应用当天未打开，允许用户后续补录。

### 3.4 手动修正规则

用户可修正：

- 上班时间。
- 下班时间。
- 午休开始 / 结束时间。
- 实际工作分钟数。
- 是否请假。
- 是否加班。
- 是否调休 / 节假日。
- 当日备注。

修正后：

- 当日收入根据修正后的工时重新计算。
- 原始自动记录不直接丢失，应写入 `record_events`。
- 手动修正优先级高于自动计算。

### 3.5 导出要求

MVP 支持导出：

- CSV。
- JSON。

导出范围：

- 当前月份。
- 自定义日期范围可作为后续增强。

## 4. 目标模块

### 4.1 模块定位

目标模块用于设置收入 / 工时目标，并判断当前进度是否正常。

### 4.2 核心功能

- 设置本月收入目标。
- 设置本月工时目标。
- 展示目标完成率。
- 展示预计月底收入。
- 展示当前进度状态。
- 支持隐私金额模式。

### 4.3 目标类型

MVP 支持：

- 月收入目标。
- 月工时目标。
- 月工作日目标。

暂不支持：

- 消费目标。
- 存钱目标。
- 预算管理。
- 季度 / 年度目标。

### 4.4 默认目标规则

如果用户未手动设置目标：

- 月薪模式：默认收入目标为当前月薪。
- 日薪模式：默认收入目标为日薪 x 本月预计工作日。
- 工时目标：默认工作日数 x 每日有效工时。

用户可以覆盖默认目标。

### 4.5 进度状态

目标模块应给出明确状态：

- 正常：当前完成率接近时间 / 工作日进度。
- 超前：当前完成率高于预期。
- 落后：当前完成率低于预期。
- 已完成：达到或超过目标。

### 4.6 隐私模式

开启隐私金额后：

- 隐藏具体金额。
- 保留百分比、状态、趋势判断。
- 不暴露月薪、日薪或目标金额。

## 5. 统计模块

### 5.1 模块定位

统计模块基于记录数据，展示收入、工时和目标达成情况。

### 5.2 MVP 统计范围

本次优先实现本月统计。

### 5.3 核心指标

统计模块展示：

- 本月累计收入。
- 今日已赚收入。
- 本月完成工作日。
- 本月剩余工作日。
- 本月累计工时。
- 平均每日收入。
- 平均每日工时。
- 目标完成率。
- 预计月底收入。

### 5.4 趋势展示

MVP 可展示轻量趋势：

- 本月每日收入列表。
- 本月每日工时列表。
- 最近 7 天收入 / 工时概览。

图表可作为增强项，不要求本次必须复杂实现。

### 5.5 异常提示

统计模块应识别基础异常：

- 工作日无记录。
- 非工作日存在收入。
- 当日工时为 0。
- 当日工时明显超过配置工作时长。
- 手动修正过的记录。

### 5.6 数据来源

统计模块优先从 SQLite 的 `daily_records` 读取数据。

如果当天记录尚未落库，可结合当前实时计算结果进行展示，但最终统计应以记录数据为准。

## 6. 模块关系

```text
实时薪资计算
  -> 生成 / 更新 daily_records
  -> 记录模块查看和修正
  -> 统计模块聚合分析
  -> 目标模块判断完成进度
```

记录模块是数据源。

统计模块是分析层。

目标模块是反馈层。

## 7. 非功能要求

- 所有数据保存在本地。
- SQLite 数据库应放在 Electron `userData` 目录。
- 数据库初始化应自动完成。
- 应支持后续数据库 schema 迁移。
- 数据写入失败不应导致主卡片崩溃。
- 历史记录不应因用户修改当前配置而被重新计算。
- 隐私金额模式应覆盖记录、目标、统计三个模块。
- 应保留导出能力，方便用户备份。

## 8. 本次不包含

本次需求不包含：

- 云同步。
- 账号体系。
- 多设备同步。
- 消费 / 预算 / 存钱管理。
- 年度报表。
- 复杂图表大屏。
- 法定节假日自动同步。
- 与外部日历集成。
- AI 总结或建议。

## 9. MVP 验收标准

- 应用能创建并初始化本地 SQLite 数据库。
- 应用配置仍通过 `config.json` 保存。
- 每日工资记录能自动生成。
- 用户能查看本月记录列表。
- 用户能手动修正单日记录。
- 用户能设置本月收入目标。
- 目标模块能显示完成率和预计月底收入。
- 统计模块能显示本月累计收入、累计工时、平均值和剩余工作日。
- 开启隐私金额后，三个模块均不显示具体金额。
- 历史记录金额不因后续修改薪资配置而变化。
